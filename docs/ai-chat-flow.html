AI chat ordering flow

A conversational ordering interface powered by Claude. Users chat with an AI assistant that browses the menu, confirms selections, and places orders — all through natural language. Built with an agentic tool-use loop inspired by the V3 TradeCapture pipeline separation pattern.

Updated in Phase 09 — Multi-Tenant. The AI chat tools (get_today_menu, place_order) are now company-scoped. The tool dispatch closure captures companyId from the JWT, so Claude can only see and order from the authenticated user's company. See the AI & analytics scoping section.

Overview

The AI chat ordering feature adds a floating chat window to the Angular frontend. When a logged-in user sends a message, the backend orchestrates a conversation with Claude (Haiku 5.5, the cheapest model at $0.10/$0.50 per MTok) using the Messages API with tool use. Claude can call two tools — get_today_menu and place_order — to interact with the canteen database on the user's behalf.

ClaudeApiService generic

A reusable, business-agnostic wrapper around the Claude Messages API. Handles the agentic loop, HTTP calls, token tracking, and tool-result plumbing. Knows nothing about canteen logic.

ChatService business

The canteen-specific orchestrator. Defines the agent (model, system prompt, tools), captures the user's identity via a lambda closure, and routes tool calls to database operations.

ChatComponent Angular

A floating chat window with a FAB button. Sends messages to POST /api/chat with conversation history, renders assistant responses in chat bubbles with a typing indicator.

V3 separation pattern. This architecture mirrors the V3 TradeCapture pipeline: ClaudeApiService is the generic engine (like V3's ClaudeService), while ChatService is the business orchestrator (like V3's TradeProcessingService). The generic service never imports domain models; the business service never touches HTTP headers or the Claude wire protocol.

Architecture

The system has four layers. Each layer only talks to the one directly below it.

DI registration

Program.csstartup

ClaudeApiService is a singleton (stateless, reusable). ChatService is scoped (one per HTTP request, so it can safely capture userId). ChatService uses IServiceScopeFactory to create fresh DI scopes for each tool call, ensuring EF Core's DbContext is properly scoped.

builder.Services.AddHttpClient();
builder.Services.AddSingleton<ClaudeApiService>();
builder.Services.AddScoped<ChatService>();

End-to-end message flow

When a user types "what's on the menu today?" in the chat window, this is the complete journey from keystroke to response.

  1. Angular ChatComponent sends message

    The component calls ChatService.sendMessage(message, history), which POSTs to http://localhost:5230/api/chat with the JWT token in the Authorization header. The request body contains the user's message and the conversation history array.

  2. ChatController extracts userId from JWT

    The [Authorize] attribute ensures only authenticated users reach the endpoint. The controller reads the NameIdentifier claim from the JWT to get the numeric userId, then calls chatService.SendMessage(req.Message, userId, req.History).

  3. ChatService builds the agent and lambda closure

    The static AgentDef holds the model (claude-haiku-5-5), system prompt, max tokens, and tool definitions. A lambda closure captures userId into the dispatch delegate: (toolName, input) => DispatchTool(toolName, input, userId). This is passed to the generic ClaudeApiService.

  4. ClaudeApiService runs the agentic loop

    Builds the messages array (history + new user message), then enters a loop of up to MaxToolRounds = 10 iterations. Each iteration calls the Claude Messages API, checks the stop_reason, and either returns text or processes tool calls. See Agentic loop for the full pseudocode.

  5. Claude decides to call get_today_menu

    The API responds with stop_reason: "tool_use" and a content block of type tool_use. The agentic loop extracts the tool name, ID, and input, then calls the dispatchTool delegate.

  6. DispatchTool routes to business logic

    The delegate flows back into ChatService.DispatchTool (with the captured userId). A C# switch expression routes "get_today_menu" to the GetTodayMenu method, which queries the database via EF Core. The result (JSON array of menu items) is returned as a string.

  7. Tool result sent back to Claude

    The agentic loop wraps the string result in a tool_result content block (matched by tool_use_id) and appends it as a "user" message. The loop continues with another API call.

  8. Claude generates the final response

    With the menu data in context, Claude formats a friendly response with item names, prices, categories, and remaining stock. This time stop_reason is "end_turn", so the loop extracts the text content and returns it.

  9. Response flows back to the UI

    The string bubbles up through ChatService → ChatController (wrapped in ChatResponse) → Angular ChatService → ChatComponent, which renders it as an assistant message bubble.

Agentic loop

The core of ClaudeApiService.SendAsync is an agentic loop that lets Claude call tools and receive results across multiple rounds. This is the same pattern used in Claude's official tool-use documentation.

Pseudocode

SendAsyncClaudeApiService

The loop has three phases: setup, loop, and post-loop.

function SendAsync(query, agentDef, dispatchTool, history):
    // ── SETUP ──
    validate API key and query
    messages = []
    append history messages (if any)
    append { role: "user", content: query }
    start stopwatch, init token counters

    // ── LOOP (max 10 rounds) ──
    for round = 0 to MaxToolRounds:
        response = POST /v1/messages with {
            model, max_tokens, system, tools, messages
        }
        accumulate input_tokens and output_tokens

        if stop_reason != "tool_use":
            // Claude is done — extract text blocks and break
            result = join all text blocks from response.content
            break

        // Claude wants to call tools
        append assistant message with raw content blocks
        toolResults = []

        for each tool_use block in response.content:
            extract name, id, input
            result = await dispatchTool(name, input)  // callback
            append { type: "tool_result", tool_use_id: id, content: result }

        append user message with toolResults array
        // loop continues — next round sends everything back to Claude

    // ── POST-LOOP ──
    log model, total tokens, elapsed time
    return extracted text

Key design decisions

MaxToolRounds = 10

Safety cap to prevent infinite loops. In practice, a menu browse + order placement takes 2–3 rounds. The cap is a guardrail, not a limit the user should hit.

Func<> delegate

The dispatch function is passed as Func<string, JsonElement, Task<string>> — a generic contract. The loop calls it without knowing what tools exist or what they do. This is what makes ClaudeApiService reusable.

Message accumulation

The messages list grows with each round: user → assistant (tool_use) → user (tool_result) → assistant (tool_use or text). Claude sees the full conversation on every API call, maintaining context across tool rounds.

Raw HTTP vs Anthropic SDK

This project uses raw HttpClient calls. The official Anthropic .NET SDK (dotnet add package Anthropic) is an alternative. The agentic loop logic is identical in both — only the HTTP/serialization layer differs.

Raw HTTP current

  • Zero extra NuGet dependency
  • Full control over JSON serialization
  • Easier to debug (see exact wire JSON)
  • Must handle headers, errors, deserialization manually
// Raw HTTP approach:
var resp = await client.PostAsync(
    "https://api.anthropic.com/v1/messages",
    content, ct);
var json = JsonDocument.Parse(
    await resp.Content.ReadAsStringAsync(ct));
// manually parse stop_reason, content blocks...

SDK alternative

  • One line replaces CallApiAsync()
  • Typed objects (ToolUseContentBlock, etc.)
  • Automatic header management
  • Adds a NuGet dependency
// SDK approach:
var client = new AnthropicClient(apiKey);
var response = await client.Messages
    .CreateAsync(parameters, ct);
// response.StopReason, response.Content
// are typed — no manual JSON parsing

Switching later. To migrate to the SDK: dotnet add package Anthropic, replace CallApiAsync() with client.Messages.CreateAsync(), and swap JsonElement content blocks for typed ContentBlock objects. The rest of the code (loop, dispatchTool, token tracking) stays identical. See the inline comments in ClaudeApiService.cs for side-by-side comparisons.

Tool dispatch

The dispatch system bridges the generic agentic loop to canteen-specific business logic. It has two parts: a lambda closure that captures context, and a switch expression that routes tool calls.

The lambda bridge

ChatService.SendMessagebridge

The ClaudeApiService.SendAsync method accepts Func<string, JsonElement, Task<string>> — a function that takes a tool name and input, and returns a result string. But DispatchTool also needs userId to place orders. The lambda closure captures it:

return await claudeApi.SendAsync(
    userMessage,
    AgentDef,
    dispatchTool: (toolName, input) => DispatchTool(toolName, input, userId),
    history,
    CancellationToken.None);

The generic service sees a two-parameter function. The business service quietly passes three. Neither side knows about the other's concerns.

The switch expression router

ChatService.DispatchToolrouter

Inside DispatchTool, a C# switch expression maps tool names to handler methods. Each call creates a fresh DI scope via IServiceScopeFactory to get a properly scoped DbContext.

private async Task<string> DispatchTool(string toolName, JsonElement input, int userId)
{
    using var scope = scopeFactory.CreateScope();
    var db = scope.ServiceProvider.GetRequiredService<CanteenDbContext>();

    return toolName switch
    {
        "get_today_menu" => await GetTodayMenu(db),
        "place_order"    => await PlaceOrder(db, input, userId),
        var unknown      => throw new NotSupportedException($"Unknown tool '{unknown}'.")
    };
}

Why IServiceScopeFactory? The agentic loop can call tools multiple times within a single HTTP request. EF Core's DbContext is scoped (one per request), but each tool call may need its own unit of work. Creating a fresh scope per tool call avoids stale tracking state and ensures each SaveChangesAsync is isolated.

Tool definitions

Tools are defined as anonymous objects in ChatService.BuildToolDefinitions() and passed to Claude in every API request. Claude uses the name, description, and input_schema to decide when and how to call each tool.

ToolDescription (sent to Claude)InputWhen Claude calls it
get_today_menu Get today's available menu items with prices, categories, and remaining stock None (empty object) User asks what's available, wants to see the menu, or before placing an order
place_order Place an order for the user. Each item needs a menuItemId and quantity { items: [{ menuItemId: int, quantity: int }] } After confirming order details with the user

Tool definition code

BuildToolDefinitions()ChatService

Tool schemas use the JSON Schema format required by Claude's Messages API. The input_schema tells Claude the exact shape of the arguments it should construct.

private static object[] BuildToolDefinitions()
{
    return
    [
        new
        {
            name = "get_today_menu",
            description = "Get today's available menu items with prices, " +
                          "categories, and remaining stock.",
            input_schema = new
            {
                type = "object",
                properties = new { },
                required = Array.Empty<string>()
            }
        },
        new
        {
            name = "place_order",
            description = "Place an order for the user. Each item needs " +
                          "a menuItemId and quantity.",
            input_schema = new
            {
                type = "object",
                properties = new
                {
                    items = new
                    {
                        type = "array",
                        items = new
                        {
                            type = "object",
                            properties = new
                            {
                                menuItemId = new { type = "integer" },
                                quantity = new { type = "integer" }
                            },
                            required = new[] { "menuItemId", "quantity" }
                        }
                    }
                },
                required = new[] { "items" }
            }
        }
    ];
}

get_today_menu

Fetches today's available menu items from the database. Returns a JSON array with item details and remaining stock, or a friendly message if nothing is available.

GetTodayMenu()ChatService

Query Joins DailyStocks with MenuItems, filters by today's date and active items, calculates remaining servings.

private static async Task<string> GetTodayMenu(CanteenDbContext db)
{
    var today = DateOnly.FromDateTime(DateTime.UtcNow);
    var items = await db.DailyStocks
        .Include(s => s.MenuItem)
        .Where(s => s.Date == today && s.MenuItem.IsActive)
        .OrderBy(s => s.MenuItem.Category)
        .ThenBy(s => s.MenuItem.Name)
        .Select(s => new
        {
            s.MenuItemId,
            s.MenuItem.Name,
            s.MenuItem.Description,
            Price = s.MenuItem.Price,
            s.MenuItem.Category,
            Remaining = s.QuantityAvailable - s.QuantityOrdered
        })
        .ToListAsync();

    if (items.Count == 0)
        return "No items are available today.";

    return JsonSerializer.Serialize(items, JsonOpts);
}

place_order

Creates an order in the database for the authenticated user. Validates stock availability, decrements quantities, and returns a confirmation string.

PlaceOrder()ChatService

Steps Parse items array → validate each against today's stock → decrement QuantityOrdered → create Order + OrderItem rows → SaveChangesAsync → return confirmation.

private static async Task<string> PlaceOrder(
    CanteenDbContext db, JsonElement input, int userId)
{
    var items = input.GetProperty("items").EnumerateArray().ToList();
    if (items.Count == 0)
        return JsonSerializer.Serialize(new { error = "No items specified." });

    var today = DateOnly.FromDateTime(DateTime.UtcNow);
    var order = new Order { Status = "Placed", TotalAmount = 0, UserId = userId };

    foreach (var line in items)
    {
        var menuItemId = line.GetProperty("menuItemId").GetInt32();
        var quantity = line.GetProperty("quantity").GetInt32();

        // Validate stock
        var stock = await db.DailyStocks
            .Include(s => s.MenuItem)
            .FirstOrDefaultAsync(s => s.MenuItemId == menuItemId
                                      && s.Date == today
                                      && s.MenuItem.IsActive);

        if (stock is null)
            return JsonSerializer.Serialize(
                new { error = $"Item {menuItemId} is not available today." });

        var remaining = stock.QuantityAvailable - stock.QuantityOrdered;
        if (quantity > remaining)
            return JsonSerializer.Serialize(
                new { error = $"Only {remaining} left for {stock.MenuItem.Name}." });

        // Decrement stock and add to order
        stock.QuantityOrdered += quantity;
        order.Items.Add(new OrderItem
        {
            MenuItemId = menuItemId,
            Quantity = quantity,
            UnitPrice = stock.MenuItem.Price
        });
        order.TotalAmount += quantity * stock.MenuItem.Price;
    }

    db.Orders.Add(order);
    await db.SaveChangesAsync();

    return $"Order #{order.Id} placed! Total: ₹{order.TotalAmount}";
}

Error handling. Tool errors are returned as JSON strings with an error field, not thrown as exceptions. Claude reads the error message and communicates it to the user in natural language (e.g. "Sorry, only 3 servings of Masala Dosa are left").

Angular chat UI

The frontend is an Angular 19 standalone component that renders a floating chat window. It appears when the user is logged in.

Component structure

FAB button

A floating action button in the bottom-right corner toggles the chat window open/closed. Uses a chat bubble icon.

Message list

Scrollable container showing user messages (right-aligned, teal) and assistant messages (left-aligned, grey). Auto-scrolls to the bottom on new messages.

Input area

Text input with a send button. Disabled during loading. Pressing Enter sends the message.

Angular ChatService

ChatServiceAngular

File client-angular/src/app/services/chat.service.ts

The Angular service sends the user's message along with the full conversation history. The JWT token is attached automatically by the HttpClient interceptor.

@Injectable({ providedIn: 'root' })
export class ChatService {
  constructor(private http: HttpClient) {}

  async sendMessage(message: string, history: ChatMessage[]): Promise<string> {
    const body: ChatRequest = { message, history };
    const res = await firstValueFrom(
      this.http.post<ChatResponse>(
        'http://localhost:5230/api/chat', body
      )
    );
    return res.reply;
  }
}

Conversation history

The chat component maintains a local array of ChatMessage objects ({ role: 'user' | 'assistant', content: string }). On each send, the full history is included in the request so the backend can pass it to Claude. This enables multi-turn conversations without server-side session state.
