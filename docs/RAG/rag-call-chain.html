App Startup — Ingestion Pipeline

RagIngestionService.cs — IHostedService runs once on startup, embeds seed documents into SQLite.

The ingestion pipeline runs automatically on startup. It reads JSON seed files, hashes each document's content, skips anything already ingested, embeds the new ones via Azure OpenAI, and stores them as BLOB columns in SQLite.

  1. Load seed data — LoadSeedDocuments() reads recipes.json and policies.json from Data/SeedData/
  2. Deduplication — FilterAlreadyIngested() computes SHA-256 of each document's content, compares against existing ContentHash values in the database
  3. Batch embedding — EmbedInBatches() sends texts to Azure OpenAI in batches of 16 (API supports up to 2048)
  4. Store — each document becomes a DocumentChunk row with the embedding serialized as byte[]
// RagIngestionService.cs — IHostedService.StartAsync
public async Task StartAsync(CancellationToken ct)
{
    var documents = LoadSeedDocuments();     // reads recipes.json + policies.json
    var newDocs = await FilterAlreadyIngested(db, documents, ct);  // SHA-256 dedup

    if (newDocs.Count == 0)
    {
        logger.LogInformation("All documents already ingested, nothing to do.");
        return;
    }

    // Embed in batches of 16 via Azure OpenAI text-embedding-3-large
    var texts = newDocs.Select(d => d.Content).ToList();
    var embeddings = await EmbedInBatches(texts, batchSize: 16, ct);

    for (int i = 0; i < newDocs.Count; i++)
    {
        db.DocumentChunks.Add(new DocumentChunk
        {
            CompanyId   = doc.CompanyId,
            Source      = /* "recipe" or "policy" based on title */,
            Title       = doc.Title,
            Content     = doc.Content,
            Embedding   = EmbeddingService.SerializeEmbedding(embeddings[i]),
            ContentHash = ComputeHash(doc.Content)   // SHA-256
        });
    }

    await db.SaveChangesAsync(ct);
}
Why content hash? On restart, the service skips documents whose content hasn't changed. If you update a recipe's text, the hash changes and it gets re-embedded. This is cheap idempotency — no duplicate rows, no wasted embedding API calls.

Claude sees the system prompt, the user's question, and three tool definitions. For “Does chicken biryani contain nuts?” it recognizes this is an ingredient/allergen question — not an order or menu query — and calls search_knowledge.

DispatchTool → RagService.SearchAsync

ChatService.cs → RagService.cs — The switch statement routes the tool call to the RAG service.

The agentic loop in ClaudeApiService extracts the tool name and input, then calls the dispatchTool delegate. In ChatService, this is a simple switch expression:

// ChatService.cs — DispatchTool
private async Task<string> DispatchTool(
    string toolName, JsonElement input, int userId, int companyId)
{
    using var scope = scopeFactory.CreateScope();
    var db = scope.ServiceProvider.GetRequiredService<CanteenDbContext>();

    return toolName switch
    {
        "get_today_menu"   => await GetTodayMenu(db, companyId),
        "place_order"      => await PlaceOrder(db, input, userId, companyId),
        "search_knowledge" => await ragService.SearchAsync(
                                  input.GetProperty("query").GetString()!, companyId),
        var unknown        => throw new NotSupportedException($"Unknown tool '{unknown}'.")
    };
}
MappingWhat happens
"get_today_menu"Queries DailyStocks + MenuItems (structured data)
"place_order"Creates an Order with stock decrement (action)
"search_knowledge"Vector search in DocumentChunks (RAG retrieval)
No magic. The mapping is a string match in a switch expression. Claude returns "search_knowledge" as a string, the switch matches it, and calls RagService.SearchAsync(). Same pattern as a controller routing a URL to a method.

Query Embedding

EmbeddingService.cs — The user's search query is converted to a vector via Azure OpenAI.

Before we can search, the query string needs to become a vector in the same embedding space as the stored documents. EmbeddingService.EmbedAsync() sends a single text to the Azure OpenAI embeddings API.

// EmbeddingService.cs — single text embedding
public async Task<float[]> EmbedAsync(string text, CancellationToken ct = default)
{
    var results = await EmbedBatchAsync([text], ct);
    return results[0];
}

// The batch method that does the actual API call
public async Task<List<float[]>> EmbedBatchAsync(
    IReadOnlyList<string> texts, CancellationToken ct = default)
{
    // POST {endpoint}/openai/deployments/text-embedding-3-large/embeddings
    //      ?api-version=2024-06-01
    // Body: { "input": ["chicken biryani nuts allergens ingredients"] }

    var url = $"{_endpoint}/openai/deployments/{_deployment}" +
              "/embeddings?api-version=2024-06-01";

    using var client = httpFactory.CreateClient();
    client.DefaultRequestHeaders.Add("api-key", _apiKey);

    var response = await client.PostAsync(url, content, ct);
    var json = await response.Content.ReadFromJsonAsync<JsonElement>(ct);

    // Returns float[3072] — text-embedding-3-large dimension
    return json.GetProperty("data").EnumerateArray()
        .OrderBy(d => d.GetProperty("index").GetInt32())
        .Select(d => d.GetProperty("embedding").EnumerateArray()
            .Select(v => v.GetSingle()).ToArray())
        .ToList();
}
ParameterValue
Modeltext-embedding-3-large
Dimensions3072 floats per vector
Authapi-key header (Azure-style, not Bearer)
Storage3072 × 4 bytes = 12 KB per chunk as BLOB

Serialization: float[] ↔ byte[]

SQLite stores embeddings as BLOB. We need to convert between float[] and byte[]:

// EmbeddingService.cs — zero-copy serialization
public static byte[] SerializeEmbedding(float[] embedding)
{
    var bytes = new byte[embedding.Length * sizeof(float)];
    Buffer.BlockCopy(embedding, 0, bytes, 0, bytes.Length);
    return bytes;
}

public static float[] DeserializeEmbedding(byte[] bytes)
{
    var floats = new float[bytes.Length / sizeof(float)];
    Buffer.BlockCopy(bytes, 0, floats, 0, bytes.Length);
    return floats;
}

Vector Search + Cosine Similarity

RagService.cs — Load company's chunks, rank by cosine similarity, return top-K.

This is the heart of RAG retrieval. SearchAsync does four things:

  1. Embed the query — get the query vector from Azure OpenAI
  2. Load company chunks — WHERE CompanyId == companyId (tenant isolation)
  3. Rank by cosine similarity — compare query vector against every chunk's embedding
  4. Return top-K — format the best matches as a context string for Claude
// RagService.cs — the core retrieval method
public async Task<string> SearchAsync(
    string query, int companyId, int topK = 3, CancellationToken ct = default)
{
    // 1. Embed the query
    var queryVec = await embedding.EmbedAsync(query, ct);

    // 2. Load all document chunks for THIS company only
    var chunks = await db.DocumentChunks
        .Where(c => c.CompanyId == companyId)   // TENANT ISOLATION
        .Select(c => new { c.Title, c.Content, c.Source, c.Embedding })
        .ToListAsync(ct);

    // 3. Rank by cosine similarity
    var results = chunks
        .Select(c => new
        {
            c.Title, c.Content, c.Source,
            Score = CosineSimilarity(queryVec,
                        EmbeddingService.DeserializeEmbedding(c.Embedding))
        })
        .OrderByDescending(r => r.Score)
        .Take(topK);

    // 4. Format as context string for Claude
    return string.Join("\n\n", results.Select(r =>
        $"[{r.Source}: {r.Title}] (relevance: {r.Score:F2})\n{r.Content}"));
}

Cosine Similarity

Measures the angle between two vectors. 1.0 = identical direction, 0.0 = orthogonal, -1.0 = opposite.

// RagService.cs — pure math, no library needed
private static float CosineSimilarity(float[] a, float[] b)
{
    float dot = 0, normA = 0, normB = 0;
    for (int i = 0; i < a.Length; i++)
    {
        dot   += a[i] * b[i];
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }
    return dot / (MathF.Sqrt(normA) * MathF.Sqrt(normB));
}
// Formula: cos(θ) = (A · B) / (||A|| × ||B||)
Tenant isolation is enforced at the database query level. The WHERE CompanyId == companyId filter runs before similarity scoring. Company A's chunks are never loaded into memory when Company B's user searches. This is a pre-filter, not a post-filter — zero data leakage.

Interview One-Liner

“I built a RAG pipeline that runs alongside the existing agentic tool-calling system. On startup, an IHostedService reads recipe and policy documents, embeds them via Azure OpenAI text-embedding-3-large, and stores the vectors as BLOBs in SQLite with a SHA-256 content hash for idempotent re-ingestion. At query time, Claude decides whether to call search_knowledge (the same way it calls get_today_menu or place_order), which triggers cosine-similarity search over the company's chunks with a CompanyId pre-filter for tenant isolation, and the top-3 results are injected into Claude's context so it generates grounded answers instead of hallucinating.”
