Building the menu

Phase-by-phase guide to adding menu items, daily stock control, and the pages that let admins manage them and employees browse today's food. Every entity, every endpoint, every component.

Updated in Phase 09 — Multi-Tenant. Menu items and daily stock are now scoped by CompanyId. Every query filters by the authenticated user's company, and SuperAdmin can see all companies. See the multi-tenant architecture doc for details.

Overview

With login done, the next thing to build is the menu. A canteen menu has two layers: a permanent catalogue of items the kitchen can make (MenuItem), and a daily selection that says which of those items are available today and how many servings remain (DailyStock). Admin users manage both; employees see only today's available items.

MenuItem catalogue

A dish the canteen offers. Has a name, description, price, category (veg, non-veg, beverage, snack), and an image URL. Admins create, edit, and soft-delete items. Items persist across days.

DailyStock today's availability

Links a MenuItem to a specific date. Holds the quantity available and how many have been ordered. When quantity hits zero, the item shows as sold out. A background job can reset stock each morning.

Roles access control

Admin can create/edit/delete menu items and set daily stock. Employee can only browse today's menu and place orders. The existing JWT already carries the Role claim.

[HttpGet] GetAllphase 2

WhatReturns all active menu items, optionally filtered by category.

HowQueries db.MenuItems.Where(m => m.IsActive). Accepts an optional ?category=Veg query parameter. Maps each entity to a MenuItemResponse record.

[HttpGet]
[Authorize]
public async Task<IActionResult> GetAll([FromQuery] string? category)
{
    var query = db.MenuItems.Where(m => m.IsActive);
    if (!string.IsNullOrEmpty(category))
        query = query.Where(m => m.Category == category);

    var items = await query
        .OrderBy(m => m.Category).ThenBy(m => m.Name)
        .Select(m => new MenuItemResponse(
            m.Id, m.Name, m.Description, m.Price,
            m.Category, m.ImageUrl, m.IsActive,
            m.CreatedAt, m.UpdatedAt))
        .ToListAsync();

    return Ok(items);
}
[HttpPost] Createphase 2

WhatCreates a new menu item. Admin only.

HowMaps the CreateMenuItemRequest to a MenuItem entity, saves it, and returns the created item with a 201 Created status and a Location header.

[HttpPost]
[Authorize(Roles = "Admin")]
public async Task<IActionResult> Create([FromBody] CreateMenuItemRequest req)
{
    var item = new MenuItem
    {
        Name = req.Name,
        Description = req.Description,
        Price = req.Price,
        Category = req.Category,
        ImageUrl = req.ImageUrl

    db.MenuItems.Add(item);
    await db.SaveChangesAsync();

}
[HttpPut("{id}")] Updatephase 2

WhatPartially updates a menu item. Admin only.

HowFinds the item by ID. If not found, returns 404. Only overwrites fields that are non-null in the request. Updates the UpdatedAt timestamp.

[HttpPut("{id}")]
[Authorize(Roles = "Admin")]
public async Task<IActionResult> Update(int id, [FromBody] UpdateMenuItemRequest req)
{
    var item = await db.MenuItems.FindAsync(id);
    if (item is null) return NotFound();

    if (req.Name is not null) item.Name = req.Name;
    if (req.Description is not null) item.Description = req.Description;
    if (req.Price.HasValue) item.Price = req.Price.Value;
    if (req.Category is not null) item.Category = req.Category;
    if (req.ImageUrl is not null) item.ImageUrl = req.ImageUrl;
    if (req.IsActive.HasValue) item.IsActive = req.IsActive.Value;
    item.UpdatedAt = DateTime.UtcNow;

    await db.SaveChangesAsync();
    return Ok(new MenuItemResponse(
        item.Id, item.Name, item.Description, item.Price,
        item.Category, item.ImageUrl, item.IsActive,
        item.CreatedAt, item.UpdatedAt));
}
[HttpDelete("{id}")] Deletephase 2

WhatSoft-deletes a menu item by setting IsActive = false. Admin only.

HowDoes not actually remove the row. This preserves order history that references the item. Returns 204 No Content.

[HttpDelete("{id}")]
[Authorize(Roles = "Admin")]
public async Task<IActionResult> Delete(int id)
{
    var item = await db.MenuItems.FindAsync(id);
    if (item is null) return NotFound();

    item.IsActive = false;
    item.UpdatedAt = DateTime.UtcNow;
    await db.SaveChangesAsync();

    return NoContent();
}

[HttpGet("today")] GetTodayphase 3

WhatReturns today's menu: every stocked item with its name, price, category, quantity available, and quantity remaining.

HowJoins DailyStock with MenuItem where Date == DateOnly.FromDateTime(DateTime.UtcNow) and MenuItem.IsActive. Computes Remaining = QuantityAvailable - QuantityOrdered.

EF Core gotcha: OrderBy must come before Select when projecting into a record constructor. If placed after, EF Core's SQLite provider throws InvalidOperationException because it cannot translate the ordering on the projected type.

[HttpGet("today")]
[Authorize]
public async Task<IActionResult> GetToday()
{
    var today = DateOnly.FromDateTime(DateTime.UtcNow);
    var items = await db.DailyStocks
        .Include(s => s.MenuItem)
        .Where(s => s.Date == today && s.MenuItem.IsActive)
        .OrderBy(s => s.MenuItem.Category)
        .ThenBy(s => s.MenuItem.Name)
        .Select(s => new TodayStockResponse(
            s.Id,
            s.MenuItemId,
            s.MenuItem.Name,
            s.MenuItem.Description,
            s.MenuItem.Price,
            s.MenuItem.Category,
            s.MenuItem.ImageUrl,
            s.QuantityAvailable,
            s.QuantityOrdered,
            s.QuantityAvailable - s.QuantityOrdered))
        .ToListAsync();

    return Ok(items);
}
[HttpPost] SetStockphase 3

WhatSets or updates the stock for a single menu item on a given date. Admin only.

HowAccepts { menuItemId, date, quantityAvailable }. If a DailyStock row already exists for that item+date, it updates the quantity. Otherwise it creates a new row. This is an upsert pattern.

[HttpPost]
[Authorize(Roles = "Admin")]
public async Task<IActionResult> SetStock([FromBody] SetStockRequest req)
{
    var item = await db.MenuItems.FindAsync(req.MenuItemId);
    if (item is null) return NotFound(new { message = "Menu item not found" });

    var existing = await db.DailyStocks
        .FirstOrDefaultAsync(s => s.MenuItemId == req.MenuItemId
                                && s.Date == req.Date);
    if (existing is not null)
    {
        existing.QuantityAvailable = req.QuantityAvailable;
        await db.SaveChangesAsync();
        return Ok(existing);
    }

    var stock = new DailyStock
    {
        MenuItemId = req.MenuItemId,
        Date = req.Date,
        QuantityAvailable = req.QuantityAvailable
    };
    db.DailyStocks.Add(stock);
    await db.SaveChangesAsync();
    return Created($"/api/stock/{stock.Id}", stock);
}
[HttpPost("batch")] SetStockBatchphase 3

WhatSets stock for multiple items at once. The admin's morning workflow: pick the items for today and set quantities in one go.

HowAccepts an array of SetStockRequest. Runs all upserts in a single SaveChangesAsync() call. Returns the full list of today's stock. Uses the same OrderBy-before-Select pattern as GetToday.

[HttpPost("batch")]
[Authorize(Roles = "Admin")]
public async Task<IActionResult> SetStockBatch(
    [FromBody] SetStockRequest[] requests)
{
    foreach (var req in requests)
    {
        var item = await db.MenuItems.FindAsync(req.MenuItemId);
        if (item is null) continue;

        var existing = await db.DailyStocks
            .FirstOrDefaultAsync(s => s.MenuItemId == req.MenuItemId
                                    && s.Date == req.Date);
        if (existing is not null)
            existing.QuantityAvailable = req.QuantityAvailable;
        else
            db.DailyStocks.Add(new DailyStock
            {
                MenuItemId = req.MenuItemId,
                Date = req.Date,
                QuantityAvailable = req.QuantityAvailable
            });
    }

    await db.SaveChangesAsync();

    var today = DateOnly.FromDateTime(DateTime.UtcNow);
    var todayStock = await db.DailyStocks
        .Include(s => s.MenuItem)
        .Where(s => s.Date == today && s.MenuItem.IsActive)
        .OrderBy(s => s.MenuItem.Category)
        .ThenBy(s => s.MenuItem.Name)
        .Select(s => new TodayStockResponse(
            s.Id, s.MenuItemId, s.MenuItem.Name,
            s.MenuItem.Description, s.MenuItem.Price,
            s.MenuItem.Category, s.MenuItem.ImageUrl,
            s.QuantityAvailable, s.QuantityOrdered,
            s.QuantityAvailable - s.QuantityOrdered))
        .ToListAsync();

    return Ok(todayStock);
}

const API = "http://localhost:5230/api";

function authHeaders(): HeadersInit {
  const auth = localStorage.getItem("auth");
  const token = auth ? JSON.parse(auth).token : "";
  return {
    "Content-Type": "application/json",
    "Authorization": `Bearer ${token}`,
  };
}

export async function getMenuItems(category?: string) {
  const url = category
    ? `${API}/menu?category=${category}`
    : `${API}/menu`;
  const res = await fetch(url, { headers: authHeaders() });
  if (!res.ok) throw new Error("Failed to load menu");
  return res.json();
}

export async function createMenuItem(data: CreateMenuItemRequest) {
  const res = await fetch(`${API}/menu`, {
    method: "POST",
    headers: authHeaders(),
    body: JSON.stringify(data),
  });
  if (!res.ok) throw new Error("Failed to create item");
  return res.json();
}

export async function getTodayStock() {
  const res = await fetch(`${API}/stock/today`, {
    headers: authHeaders(),
  });
  if (!res.ok) throw new Error("Failed to load stock");
  return res.json();
}

Security + access control

What the design provides

  • Role-based access. The JWT already carries the Role claim. [Authorize(Roles = "Admin")] on endpoints enforces server-side access control.
  • Soft-delete. Menu items are never hard-deleted, preserving referential integrity with future orders.
  • Frontend guards. AdminRoute prevents employees from seeing admin pages, but the real enforcement is on the API.
  • Unique constraint on daily stock. The composite index on (MenuItemId, Date) prevents duplicate entries.

Things to consider

Worth addressing as the app grows.

  • No admin creation flow. Currently, setting a user's role to Admin requires direct database access. Consider an admin-invite endpoint or a seed admin.
  • No input validation. Negative prices or negative quantities are not rejected. Add [Range] annotations or FluentValidation.
  • No pagination. The menu list returns all items. Fine for a small canteen; add skip/take if the catalogue grows.
  • No image upload. ImageUrl is a raw string. Consider a file upload endpoint or a CDN integration.
  • Timezone handling. DateOnly.FromDateTime(DateTime.UtcNow) uses UTC. The canteen's local date may differ. Consider using the canteen's timezone.

What comes next

With the menu in place, the next major feature is ordering. The ordering flow builds directly on menu management:

  1. OrderController — place order, cancel, update status (placed → preparing → ready → collected).
  2. Stock decrement — when an order is placed, DailyStock.QuantityOrdered is incremented atomically.
  3. Order history — employees can view their past orders.
  4. Kitchen view — a real-time dashboard of incoming orders for kitchen staff (using SignalR).
  5. Feedback — post-meal rating and comment system, leading to the AI triage service.

The ordering phase will add Order and OrderItem entities, an OrderController, and modify DailyStock to decrement available quantities. This is designed to be the next document in this series.
